WebDAV Service

Active

Expose your VFS directory tree as a WebDAV server.

Server Connection

0 (recommended) lets the OS assign an available port; avoid reserved ports.

Address: <your-connection-url>

The real page fills this in automatically from GET /api/services/webdav-vfs-mount/config — the actual value differs by deployment (see below). This mockup deliberately does NOT hardcode a URL/port: an earlier draft did (localhost:9876), which was wrong for every real deployment.

What "<your-connection-url>" resolves to

  • Multi-user Bastion deployment:
    https://<your-bos-hostname>/__supervisor/services/webdav-vfs-mount/
  • Supervisor-only (no Bastion, e.g. self-hosted Dokploy):
    http://<your-host>:<public-port>/__supervisor/services/webdav-vfs-mount/ — <public-port> is whatever the operator set (default 8080)
  • Standalone (no Supervisor, e.g. plain npm run dev):
    http://localhost:<dynamic-port>/ — a different OS-assigned port every restart

See docs/dev/apps/services.md §11 for the full mechanism.

Connection Instructions

Windows

In the "Network Drive" wizard, enter the URL shown above:

<your-connection-url>

Use webdav as the username and your access token as the password.

macOS

Open Finder → Go → Connect to Server, using the URL shown above (with dav:// in place of http:///https://):

dav://<your-connection-host-and-path>/

Enter your access token when prompted for the password.

Linux (davfs2)

Install davfs2, then mount the share using the URL shown above:

sudo mount -t davfs -o username=webdav,password=YOUR_TOKEN <your-connection-url> /mnt/webdav

Replace YOUR_TOKEN with your generated access token.

Access Token

Generate an access token to authenticate your WebDAV clients.

Security: The access token is the only protection against unauthorized access. Treat it like a password — never share it or commit it to version control.
